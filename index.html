Core Features

Everything the campus needs,
in one app.

Designed around the real daily friction of hostel life at AKGEC — from Sachi Street errands to placement prep anxiety.

🗺️

Live Campus Radar

Animated hotspot map shows open quests near Sachi Street, Main Canteen, and hostels in real time via Socket.io broadcasts.

📋

Post a Quest

5-step form with item description, AKGEC pickup/drop-off locations, a QP/cash bounty slider, and a live preview card before posting.

⚡

Race-safe Claiming

SELECT FOR UPDATE SKIP LOCKED ensures only the first courier wins. All others receive an instant 409 — no queuing, no double-assigns.

🎓

Talk to a Senior

Q&A forum with tag filters (Placements, DSA, GATE, Backlog…), nested replies, upvote toggles, and a 25 QP bonus at 10 upvotes.

🪙

Quest Points Economy

Append-only QP ledger, 6-tier level system (Freshman → Campus Legend), and redeemable perks at real Sachi Street shops.

🏆

Gamification

Level progress bars, day streaks, campus rank, and animated reward cards. QP tier auto-recalculates via PostgreSQL trigger on every update.

Tech Stack

Production-grade architecture,
campus-scale scope.

Every layer chosen to solve a specific problem — not just assembled from defaults.

Frontend

React Native (Expo ~51)

  • React Navigation v6 — NativeStack + custom 5-tab bar with FAB center button
  • expo-linear-gradient — gradient tiles for action grid and hero banner
  • Animated API — PanResponder slider, spring claim animation, radar sweep rotation
  • Design system — tokens for color, typography, spacing, shadow (Blue & White theme, QP Gold accent)
  • State management — local useState per screen; no external store needed at this scale
Backend

Node.js + Express + Socket.io

  • PostgreSQL (pg pool) — single shared Pool, withTransaction() helper, idempotent migration runner
  • SELECT FOR UPDATE SKIP LOCKED — non-blocking row-level lock for concurrent quest claiming
  • Socket.io rooms — quests:open (radar), quest:id (per-quest), user:id (private QP updates), forum
  • JWT + bcryptjs — stateless auth with role-based access (student / senior / admin)
  • Append-only transactions table — mutation-block triggers prevent ledger tampering
Database

PostgreSQL Schema Design

  • Enum types — quest_status, user_role, gamification_tier, bounty_type, thread_tag
  • Status guard trigger — rejects illegal quest state jumps (e.g. open → completed) at DB level
  • Auto-tier trigger — recalculates gamification tier on every qp_balance update
  • Partial index — WHERE status = 'open' for fast radar feed queries
  • pg_trgm GIN index — full-text thread search without a search engine dependency
Security & Ops

Middleware & Reliability

  • Helmet — sets 11 security response headers automatically
  • 3-tier rate limiting — general (100/min), auth (10/min), claim (5/min, keyed per user)
  • Global error handler — maps pg error codes (23505, 23514…) to typed HTTP responses
  • Graceful shutdown — SIGTERM drains HTTP + Socket.io + DB pool before exit
  • asyncHandler wrapper — eliminates try/catch boilerplate in every controller

Architecture Deep-Dive

How the claim race condition
is actually solved.

50 couriers tap "Claim" simultaneously. Here's exactly what happens at the database level.

POST /quests/:id/claim — Concurrency Flow
SELECT FOR UPDATE SKIP LOCKED — non-blocking, database-native
🚀
BEGIN TX
Transaction opened on dedicated PG client
🔒
SKIP LOCKED
Try to lock row WHERE status='open'. Returns 0 rows if already locked.
🔍
Discriminate
0 rows = race lost (409) or not found (404) or unavailable (409)
✅
UPDATE + Escrow
Set courier_id, status='claimed', debit QP from requester
📡
COMMIT + Broadcast
emitQuestClaimed() removes card from all radar clients instantly
No application-level mutex No Redis lock DB is single source of truth All losers get instant 409 Crash-safe (ROLLBACK on error)
